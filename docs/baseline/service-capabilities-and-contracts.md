React mounts the `Booking` overlay (`src/parts-cartographer/app.jsx:22, 324-331`), implemented in `src/parts-cartographer/overlays.jsx:664-860`; its `Therapist` overlay saves owner availability and lets the owner approve or decline pending appointments (`src/parts-cartographer/overlays.jsx:955-992, 1025-1089`). The therapist screen uses a client-side self-attestation flag stored in localStorage (`src/parts-cartographer/overlays.jsx:998-1008`), not a verified credential or server role. The Angular `BookingPanelComponent` is a separate UI (`src/app/features/booking-panel/booking-panel.component.ts:31-49`), while its `booking.ts` is only a compatibility re-export of the React shared Firestore service (`src/app/features/booking-panel/booking.ts:1-3`). Thus the two front ends overlap on discovery, scheduling, consent and request creation, using `src/parts-cartographer/core/booking.ts`; their UI guards and error paths differ. ## Verified contract boundaries and open verification

- **Roles:** Firebase identity verification yields UID, email, and verified-email boolean; the Worker does not consume custom role claims in `worker-security.ts:57-61`. Firestore admin access is based on verified-email allowlist, while therapist data permissions arise from record ownership and appointment/share relationships (`firestore.rules:23-35, 324-335`). Do not claim an authenticated account has a therapist/admin role merely because it is signed in, or because it owns a therapist document.
- **Booking availability:** A real therapist profile and explicit schedule are prerequisites. The default schedule in the helper is a code fallback, not live availability. A slot generated from wall-clock data is not a timezone-safe offer. Booking is a request (`pending`) until an authorized participant changes status.
- **Booking partial failure:** the appointment and busy lock commit as one batch; client share and therapist roster are later writes. Recovery needs reconciliation/retry or an explicit incomplete state if either later write fails. Confirm the UI does not report full success just because the first batch committed.
- **AI:** local fallback is useful degraded behavior, not cloud inference. Provider secrets and rate limiting must be present in deployed Worker environment; provider candidates in code are not proof of credentials, reachability, or successful output.
- **Entitlement:** checkout-session verification is the entitlement boundary. A successful checkout URL/redirect is not a verified purchase. Client cache is time-bounded and browser-local; it is not an authoritative role claim.
- **Evidence classification:** source/config inspection only for this artifact. Emulator ports and test files indicate test affordances, not that an emulator test was run. No preview build, Firebase emulator, deployed Firebase, Cloudflare Worker, AI provider, Stripe, booking, or production flow was exercised. No claim about production availability, correctness, or configuration is made.
